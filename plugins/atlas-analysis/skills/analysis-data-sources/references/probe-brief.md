# Bounded ServiceX worker brief

Supply only relevant specification excerpts, requirement IDs and exact
definitions/units, sample DID/role/production, the installed ServiceX skill and
the evidence contract, and the absolute analysis workspace. The steering model
owns the root deliverables; workers must not relocate or overwrite them. Ask the
luna worker to:

1. Discover release-matched accessors and retained content for these fields.
2. Write and execute a one-file ServiceX probe with event identity and a known
   positive-control field; preserve sidebands and object alignment.
3. Inspect delivered output and retain code/logs locally. Return compact ledger
   records with the exact executed query and essential helpers, dataset/request,
   versions, column/count/type/unit/range evidence, and concise diagnostics. Do
   not create a debug archive or return every attempt as a separate deliverable.
4. Isolate failure and attempt at most two evidence-based repairs. Return
   diagnostics when blocked. Do not change definitions, invent defaults, move
   to a richer derivation or request full datasets independently.

The steering model decides whether the failure proves a gap, whether to try
PHYS, and whether a proxy is scientifically acceptable. Review executed code and
artifacts rather than trusting the final message. Record actual worker models
and escalation, and the limits of any model comparison.
